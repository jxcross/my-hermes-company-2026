# 요약

- **결론:** 온디바이스 LLM 추론 최적화는 가중치 압축, KV cache, DRAM–Flash 계층 배치, 런타임·하드웨어 가속을 함께 조정하는 **조건부 trade-off**이며, 평균 token/s 하나가 아니라 TTFT·TPOT·peak memory·품질·전력/열·지원 행렬을 같은 장치와 workload에서 공동 측정해 배포를 결정해야 한다. [MobileLLM](https://arxiv.org/abs/2402.14905v2) · [KIVI](https://arxiv.org/abs/2402.02750v2) · [LLM in a Flash](https://arxiv.org/abs/2312.11514v3) · [MLPerf Inference v5.0](https://mlcommons.org/2025/04/llm-inference-v5)

- **범위와 성숙도:** 구조·가중치 압축, KV cache, DRAM–Flash, 요청 적응형 SLO 조정은 논문·제안 또는 제한된 실험 조건에 근거한 **연구** 단계로, 런타임/하드웨어 가속, RAG·function calling, 모델·메모리 가변화, 평가 도구 경로는 구현물·제품 경로는 있으나 지원·비교·운영 조건이 제한된 **초기** 단계로 분류한다. 이 분류는 보편적 성능 우위를 뜻하지 않으며, 각 성능 수치는 장치·정밀도·런타임·문맥 길이 조건 밖으로 일반화하지 않는다. [MobileLLM](https://arxiv.org/abs/2402.14905v2) · [KIVI](https://arxiv.org/abs/2402.02750v2) · [ElastiLM](https://arxiv.org/abs/2409.09071v2) · [MNN-LLM](https://arxiv.org/abs/2506.10443v1) · [LLM in a Flash](https://arxiv.org/abs/2312.11514v3) · [Google AI Edge SLM 발표](https://developers.googleblog.com/en/google-ai-edge-small-language-models-multimodality-rag-function-calling) · [Gemma 3n 발표](https://developers.googleblog.com/introducing-gemma-3n) · [MLPerf Client v1.0](https://mlcommons.org/2025/07/mlperf-client-v1-0)

- **우선 적용:** 먼저 장치별 측정 harness를 고정하고, 동일 모델에서 저비트 weight PTQ의 품질 gate·메모리·TTFT·TPOT을 함께 측정한다. 이어 KV cache는 문맥 길이와 attention 구조별 실험 축으로, DRAM–Flash 배치는 storage throughput·cache eviction·first-token 비용·전력/열·동시 요청을 포함한 제한적 실험으로 다룬다. [MLPerf Inference v5.0](https://mlcommons.org/2025/04/llm-inference-v5) · [MobileLLM](https://arxiv.org/abs/2402.14905v2) · [KIVI](https://arxiv.org/abs/2402.02750v2) · [LLM in a Flash](https://arxiv.org/abs/2312.11514v3) · [MNN-LLM](https://arxiv.org/abs/2506.10443v1)

- **제품화 경계:** Android RAG와 function calling은 내부 기능 pilot으로 제한하고, 함수 allowlist·인자 검증·권한/실패 처리·오프라인 데이터 갱신·retrieval 품질/지연을 검증한다. Android AICore와 Snapdragon NPU는 OS/SoC/API·모델·정밀도별 지원 행렬, 라이선스·배포 산출물, local endpoint의 오류·호환 범위를 사전 확인하는 배포 후보로 분리하며, SLO-aware 선택과 Gemma 3n은 연구 또는 preview track에서만 평가한다. [Google AI Edge SLM 발표](https://developers.googleblog.com/en/google-ai-edge-small-language-models-multimodality-rag-function-calling) · [Gemini Nano/AICore 문서](https://ai.google.dev/gemini-api/docs/get-started/android_aicore) · [QAI AppBuilder 문서](https://docs.qualcomm.com/doc/80-94755-1/80-94755-1_REV_AA_QAI_AppBuilder_-_WoS.pdf) · [ElastiLM](https://arxiv.org/abs/2409.09071v2) · [Gemma 3n 발표](https://developers.googleblog.com/introducing-gemma-3n)

- **검증 상태:** 단일 검증표의 21개 핵심 주장 가운데 **확인 12건, 상충 0건, 미검증 9건**이며 최종 판정은 **PASS**다. PASS는 미검증 항목의 귀속과 한계를 공개했다는 게이트 판정이지, 미검증 주장이 확인된 사실이 되었다는 뜻은 아니다. [Google AI Edge SLM 발표](https://developers.googleblog.com/en/google-ai-edge-small-language-models-multimodality-rag-function-calling)

- **미검증·인용 제한:** 미검증 9건은 2025-05-20 당시의 인벤토리·릴리스 상태, 공급자만 제시한 수치·효능, 또는 ‘첫’·‘한 페이지’ 같은 공급자 분류/마케팅 표현에 해당하므로 공급자 발표로만 귀속한다. 특히 int4의 `2.5–4×` 축소, 1,000페이지/사진 검색, tool simulation의 정확도 향상, 당시 SDK 가용성은 일반 효과나 과거 배포 사실로 승격하지 않는다.
